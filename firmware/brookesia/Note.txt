Waveshare 7inch DSI LCD (H) + ESP32-P4-Module-DEV-KIT 에서 brookesia 펌웨어 동작시키기
================================================================================

작업일: 2026-10-03
저장소: https://github.com/Sunyoup/ESP32-P4-Platform (waveshareteam/ESP32-P4-Platform 의 fork)
대상:   firmware/brookesia


1. 목적
-------
ESP32-P4-Platform 이 공식 지원하지 않는 Waveshare 7inch DSI LCD (H) 를 LCD 타입
옵션으로 추가하고, firmware/brookesia 를 빌드해서 실제 보드에서 동작시킨다.


2. 하드웨어
-----------
- 보드: Waveshare ESP32-P4-Module-DEV-KIT
    칩 리비전 v1.0 (구형), flash 16MB, PSRAM 32MB, 무선은 ESP32-C6 (SDIO)
- LCD: Waveshare 7inch DSI LCD (H)
    1280x720 가로(landscape), DSI 2 lane, RGB888 만 지원
- 카메라: OV5647 (MIPI-CSI)

자료에 나오지 않아 보드에서 직접 확인한 사실:
- 화면 쪽은 특정 컨트롤러 초기화 시퀀스가 필요 없다. 패널 보드의 MCU(I2C 0x45)에
  전원/백라이트 레지스터를 쓰고, 표준 DCS 명령 0x11, 0x29 만 보내면 된다.
- 터치 칩은 Goodix GT927 (I2C 0x14, 부팅 로그 TouchPad_ID "927").
  GT911 드라이버로 동작한다.
- 터치 패널은 세로 720x1280 좌표를 내며 화면에 대해 90도 돌아가 있다.
  네 모서리에서 측정한 원시 좌표 (x, y):
    왼쪽 위 (685, 32)   오른쪽 위 (682, 1239)
    왼쪽 아래 (17, 35)  오른쪽 아래 (25, 1244)
  변환식: 화면 X = 터치 Y, 화면 Y = 719 - 터치 X
- 백라이트는 다른 Waveshare 패널의 0x96 레지스터가 아니라
  0xAB (255 - 밝기값, 반전) 을 쓰고 0xAA = 1 로 적용한다.


3. 빌드 환경
------------
- ESP-IDF v5.5.5 로 빌드한다 (셸 alias: get_idf555).
- ESP-IDF v6.1 에서는 빌드되지 않는다. brookesia_core 가 요구하는 json 컴포넌트가
  v6 에서 제거되어 configure 단계에서 실패한다 (수정 전 원본도 동일).

빌드:
    cd firmware/brookesia
    get_idf555
    rm -f sdkconfig
    idf.py -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.rev1_3.defaults;sdkconfig.7_dsi_lcd_h.defaults" build

  - sdkconfig.rev1_3.defaults : 칩 리비전 v3.0 미만용 프로파일
  - sdkconfig.7_dsi_lcd_h.defaults : 이 LCD 와 16MB flash 용 프로파일 (이번에 추가)
  - 기존 sdkconfig 가 남아 있으면 defaults 가 적용되지 않으므로 먼저 지운다.

주소 0 기준 병합 이미지 만들기:
    cd build
    python -m esptool --chip esp32p4 merge_bin -o ../merged.bin @flash_args

플래시:
    전체:   python -m esptool --chip esp32p4 -p /dev/ttyACM0 -b 921600 write_flash 0x0 merged.bin
    앱만:   python -m esptool --chip esp32p4 -p /dev/ttyACM0 -b 921600 write_flash 0x110000 build/esp-brookesia.bin
  -b 921600 을 주지 않으면 매우 느리다 (전체 이미지 15.8MB).

시리얼 콘솔 속도는 2,000,000 baud 이다 (upstream 기본 설정).


4. 브랜치와 단계별 작업
-----------------------
main 에서 시작해 단계마다 브랜치를 하나씩 쌓았다. 이름은 모두
"7-DSI-LCD-H_brookesia_" 로 시작한다.

initial
    main 과 같은 시작점.

step1_local_bsp
    LCD 타입 옵션(CONFIG_BSP_LCD_TYPE_*)은 저장소가 아니라 컴포넌트 레지스트리의
    waveshare/esp32_p4_platform 에 들어 있다. 그래서 2.0.1 을 수정 없이
    components/esp32_p4_platform 으로 복사하고, product_support 의 레지스트리 의존을
    제거했다. examples/ 는 여전히 레지스트리 BSP 를 쓴다.

step2_lcd_type
    BSP 에 BSP_LCD_TYPE_1280_720_7_INCH_H 추가.
    - 패널 구동은 BSP 가 이미 의존하던 waveshare/esp_lcd_dsi 드라이버 사용.
      이 드라이버는 I2C_NUM_1 (GPIO7/8) 을 직접 열지만, BSP 가 먼저 연 버스를
      재사용하므로 충돌하지 않는다 (CONFIG_BSP_I2C_NUM=1 이어야 함).
    - 이 타입에서는 RGB565 선택지를 숨기고, LVGL 색 깊이가 24 가 아니면 컴파일 오류.
    - 밝기 설정과 Settings 의 밝기 읽기를 0xAB/0xAA 레지스터에 맞게 수정.

step3_board_profile
    sdkconfig.7_dsi_lcd_h.defaults 추가: LCD 타입, RGB888, LVGL 24비트, flash 16MB.

step4_stylesheet
    brookesia 에 1280x720 용 스타일시트가 없어서 1280_800 을 바탕으로 1280_720 을
    새로 만들고 main.cpp 에서 선택하도록 했다. 앱 런처는 200px 아이콘 2행,
    최근 앱 스냅샷은 16:9.

step5_rgb888_squareline
    SquareLine 데모 앱 이미지가 RGB565 데이터인데 NATIVE 포맷으로 선언되어 있어
    24비트 LVGL 에서 빌드가 막혔다. 실제 포맷(RGB565 / RGB565A8)으로 선언을 고쳤다.
    전체 빌드는 이 단계부터 통과한다 (step3, step4 만으로는 실패).

step6_docs
    firmware/README.md, README_CN.md 에 빌드 방법 기재.

step7_touch_rotation
    터치 좌표를 화면 좌표로 변환 (2장의 변환식).

step8_pixel_clock
    픽셀 클럭을 80MHz 에서 50MHz 로 낮춤 (5장 참고).

step9_camera_mode
    OV5647 센서 모드를 800x1280 에서 1280x960 binning 으로 변경.
    기존 모드는 센서 일부를 세로로 잘라 읽는 모드라, 가로 화면에서는 800x450 띠만
    1.6배 확대되어 너무 확대되고 광축이 어긋나 보였다. 새 모드는 전체 화각이고
    가운데 1280x720 을 확대 없이 쓴다.
    카메라 앱의 대체 캡처 크기가 800x1280 으로 고정되어 있던 것을 센서가 알려 주는
    크기를 쓰도록 고쳤다.

step10_camera_copy
    카메라 미리보기 속도 개선과 안정화 (6장 참고).

step11_notes
    이 문서.

step12_ethernet
    보드의 유선 랜 포트 지원 추가. 원래 펌웨어에는 이더넷 초기화 코드가 없어서
    랜선을 꽂아도 반응이 없었다.
    - product_support 에 product_ethernet_start() 추가 (src/product_ethernet.c).
      내장 EMAC + IP101 PHY, MDC=GPIO31, MDIO=GPIO52, PHY 리셋=GPIO51, PHY 주소 1,
      RMII 핀은 ESP32-P4 기본값.
    - 랜선이 꽂히면 DHCP 로 주소를 받는다. 화면에는 표시하지 않고 로그로만 나온다:
        product_ethernet: Ethernet link up
        product_ethernet: Ethernet got IP 192.168.x.x, mask ..., gateway ...
    - 이더넷 시작에 약 2.2초가 걸려서, 화면이 먼저 뜨도록 UI 가 올라온 뒤에
      main.cpp 끝부분에서 호출한다.
    - 네트워크 스택과 기본 이벤트 루프는 Settings 앱의 Wi-Fi 초기화와 공유한다.

step13_timezone
    Wi-Fi 로 NTP 시각을 맞추면 한 시간 느리게 표시됐다. Settings 앱이 시간대를
    "CST-8" (중국 표준시, UTC+8) 로, NTP 서버를 ntp.aliyun.com 으로 고정해 두었기
    때문이다.
    - components/Settings/Kconfig 추가: CONFIG_SETTINGS_TIMEZONE (기본 "CST-8"),
      CONFIG_SETTINGS_NTP_SERVER (기본 "ntp.aliyun.com"). 기본값은 upstream 과 같다.
    - sdkconfig.7_dsi_lcd_h.defaults 에서 "KST-9" (한국 표준시, UTC+9) 와
      "pool.ntp.org" 로 지정.
    - 시각 동기화는 Wi-Fi 가 주소를 받았을 때 시작한다. 유선 랜만 연결된 상태에서는
      동기화하지 않는다.


5. 화면 깜빡임 (DSI underrun)
-----------------------------
증상: 터치 등으로 화면을 다시 그릴 때 깜빡이고, 로그에
    "lcd.dsi: can't fetch data from external memory fast enough, underrun happens"

원인: 칩 리비전 v3.0 미만은 DSI 브리지의 입력/출력 포맷 레지스터가 하나뿐이라
프레임버퍼 포맷이 곧 DSI 선로 포맷이다. 이 패널은 RGB888 만 받으므로 프레임버퍼도
RGB888 이어야 하고, 이것을 200MHz PSRAM 에서 80MHz 픽셀 클럭으로 읽어 내는 것이
화면을 그리는 동안에는 버겁다. (v3.0 이상 칩이라면 프레임버퍼는 RGB565 로 두고
출력만 RGB888 로 변환할 수 있다.)

부팅 중 underrun 횟수 측정 (터치 없이):
    80MHz (벤더 기본값)                     11
    80MHz + 주사용 DMA 의 AXI 우선순위 상향  11  (효과 없음)
    80MHz + XIP from PSRAM 끔               18  (악화)
    60MHz                                    4
    50MHz                                    0

결론: 50MHz 로 설정. 주사율은 약 60Hz 에서 약 37Hz 가 된다. 이후 터치 조작과
카메라 실행 중에도 underrun 0 을 확인했다.


6. 카메라 미리보기 속도
-----------------------
구간별 측정 (프레임당):
    방식                      복사 시간   fps
    PPA (원래 코드)            69.7ms    11.3
    CPU memcpy                 93.4ms     9.0
    LCD 드라이버 DMA2D 직접    28.0ms    22.5   (표시 중인 버퍼에 써서 tearing 발생)
    AXI-GDMA 비동기 복사       41.9ms    21.8   (채택, tearing 없음)

채택한 방식:
- 확대/축소가 필요 없을 때는 PPA 대신 esp_async_memcpy (AXI-GDMA) 로 카메라 버퍼의
  가운데 영역을 LCD 프레임버퍼에 복사한다. 확대가 필요한 경우는 그대로 PPA.
- LCD 프레임버퍼 3개를 돌려 써서 표시 중인 버퍼에는 쓰지 않는다 (tearing 방지).
- 복사는 256KB 조각으로 나누고 backlog 는 1 로 둔다. 비동기 복사 드라이버가 최근
  backlog 건의 DMA 목록을 내부 RAM 에 들고 있어서, 프레임 전체를 한 번에 보내면
  내부 RAM 이 부족해졌다.
- 카메라 버퍼(3.7MB x 2)는 처음 한 번만 할당하고 앱을 닫아도 유지한다. 열 때마다
  할당/해제하면 PSRAM 이 조각나서 세 번째 실행에서 할당이 실패했다.

22fps 는 센서 45fps 의 두 프레임마다 한 장을 표시하는 속도다.

참고: 카메라를 열 때마다 "csi_video: width or height is not supported" 오류가
두 줄 찍힌다. 앱이 화면 크기로 캡처를 먼저 시도했다가 센서 크기로 넘어가는 원래
동작이며 무해하다.


7. 보드에서 확인한 것
---------------------
- 화면 표시와 색
- 터치 위치와 쓸어 넘기는 방향
- 화면 깜빡임 없음
- 밝기 슬라이더, 소리 볼륨 슬라이더
- 카메라 (화각, 방향, 속도, tearing 없음, 반복 실행)
- Video Player (SD 카드), Music Player
- 유선 랜: 링크 업 후 DHCP 로 192.168.76.43 을 받는 것을 로그로 확인, PC 에서 ping 응답 확인


8. 남은 과제
------------
- 주사율이 약 37Hz 다. 블랭킹(porch)을 줄이면 50MHz 를 유지하면서 50Hz 근처로
  올릴 수 있을 것으로 보이나, 벤더 타이밍(전후 porch 각 64)을 벗어나므로 패널이
  받아 주는지 실험이 필요하다.
- Wi-Fi 동작은 확인하지 않았다 (ESP32-C6 와의 SDIO 연결까지는 로그로 확인).
- 유선 랜은 주소 할당과 ping 까지만 확인했다. 앱에서의 사용(시간 동기화 등)과
  Wi-Fi 와 동시에 쓸 때의 경로 우선순위는 확인하지 않았다. 유선 연결 상태를 화면에
  표시하는 기능은 넣지 않았다.
- firmware/README.md 에는 빌드 방법만 있고 터치/픽셀 클럭/카메라 내용은 없다.
- 1280_720 스타일시트 수치는 계산으로 정한 것이라 취향에 따라 조정 여지가 있다.
- 칩 리비전 v3.x 보드에서는 시험하지 않았다.
